# SOP-13 — OCR-safe letters & evidence checklist

**Purpose:** Maximize deliverability and credibility of letters and exhibits; avoid bulk-template detection.

---

## Evidence checklist (per disputed account)

- [ ] Report pull date recorded
- [ ] Screenshot shows bureau header or context (not cropped to score only)
- [ ] Account label matches dispute candidate (`creditorName` / collection row label)
- [ ] For collections: evidence `sectionKey` `collections` or `collections_tradeline` as appropriate
- [ ] Fields disputed are **visible** on screenshot (balance, DOFD, status, etc.)
- [ ] Stored in Vault with partner scope

---

## OCR / template checklist (per letter batch)

- [ ] Used template variant or manual reorder (not 10× identical body)
- [ ] Opening paragraph customized to account type (collection vs charge-off vs inquiry)
- [ ] Exhibit references numbered and match attachments
- [ ] No contradictory dates vs report exhibit
- [ ] PDF export is crisp text (Admin Templates: OCR-friendly layout)
- [ ] If reusing prior company language, rewrite structure (SOP-14)

---

## Variation techniques (pick ≥2 per batch)

1. Reorder sections: facts → request → exhibits vs request → facts → law cite
2. Swap clause bank lines from `negativePlaybooks.ts` clauses
3. Change salutation block and account identifier layout
4. Use different template `version` in starter pack when available
5. Per-bureau letters only where reporting differs (do not assume tri-merge sameness)

---

## Review before mail

- [ ] Specialist peer or lead spot-check on first solo file
- [ ] Mailing address verified against report or collector letter
- [ ] Certified receipt workflow ready
